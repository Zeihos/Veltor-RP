# Развёртывание сайта и форума

## Требования

- PHP 8.1+ (с поддержкой сессий, JSON и `password_hash`/`password_verify`);
- HTTPS и корректная настройка PHP-хостинга;
- запись в отдельный `storage/` каждого приложения;
- Apache 2.4 с разрешённым чтением `.htaccess` **или** Nginx с явно настроенными запретами.

Две программы независимы: единого входа между сайтом и форумом пока нет. MySQL здесь не требуется.

## Рекомендуемая структура на хостинге

```text
/var/www/veltor/
  site/           содержимое Сайт/
  forum/          содержимое Форум/
```

Настройте два веб-хоста: `site.example` -> `site/`, `forum.example` -> `forum/`. Домен в примере условный, реальный адрес нужно указать в панели хостинга. **Не делайте корнем сайта весь Git-репозиторий:** иначе `tests/`, `docs/` и другие служебные файлы станут доступны снаружи.

### Apache

Включите обработку PHP и `AllowOverride` для обоих документ-корней — чтобы работали файлы `.htaccess`. Перед публикацией проверьте, что запросы `/app/core.php`, `/storage/index.php` и `/.htaccess` возвращают **403**. Не полагайтесь только на то, что файлы базы имеют расширение `.php`.

### Nginx

Файлы `.htaccess` на Nginx игнорируются. Добавьте правила из [`deploy/nginx-restrictions.conf`](../deploy/nginx-restrictions.conf) **внутрь каждого** блока `server {}`, настройте PHP-FPM и проверьте HTTP-запреты до открытия доступа.

### Установка

1. Настройте HTTPS и доступ PHP на запись в `storage/`, запретив HTTP-доступ к нему.
2. Откройте `/install.php` сайта, создайте администратора с уникальным длинным паролем.
3. То же проделайте отдельно на форуме (администраторы НЕ синхронизированы).
4. В панели управления установите реальные ссылки, заполните данные серверов и новости, проверьте права доступа.
5. Проверьте блокировку `/app/`, `/storage/`, временных файлов и защиту форм.
6. Настройте резервное копирование двух `storage/` **вне публичных директорий** и пробное восстановление. Не загружайте копии в Git.

## Проверки после установки

```bash
curl -I https://site.example/app/core.php
curl -I https://site.example/storage/index.php
curl -I https://site.example/.htaccess
```

Все три запроса должны возвращать запрет доступа (обычно `403`). Повторите для форума. Стартовые страницы и CSS, напротив, должны открываться.

## Что ещё не готово для масштабной публичной эксплуатации

Нет общей системы аккаунтов, платёжной интеграции, автоматического мониторинга сервера и подтверждения почты. Для большого сообщества потребуются антиспам/CAPTCHA, журналирование, контроль резервных копий, мониторинг ошибок и нагрузочное тестирование. Локальный PHP-сервер `php -S` запрещено использовать как публичный хостинг.
